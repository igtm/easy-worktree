# `wt clean` のインタラクティブな複数選択削除 (Interactive bulk cleanup via fzf)

## Summary
`wt clean` コマンドにインタラクティブモード（`-i` または `--interactive`、あるいは引数なしのデフォルト挙動）を追加し、`fzf` の複数選択（multi-select）を用いて不要な worktree を一括削除できるようにする機能。

## Problem
開発を長く続けていると、マージされずに放置された実験的なブランチや、PR がクローズされた作業途中の worktree が `.worktrees/` 以下に多数蓄積していく。
現在、一括削除の手段として `wt clean --merged` や `--days N` などの条件指定コマンドは用意されているが、「残すもの」と「消すもの」を人間が視覚的に判断して取捨選択したいケースも多い。
その場合、ユーザーは `wt list` で一覧を確認しながら、手作業で `wt rm feature-A`, `wt rm experiment-B` ... と何度もコマンドを叩く必要があり、定期的なお掃除作業のハードル（摩擦）が高くなっている。

## Proposal
`wt clean -i`（または引数なしで `wt clean`）を実行した際、`fzf` の画面を立ち上げ、存在する worktree の一覧から削除対象を対話的に選べるようにする。

**挙動のイメージ:**
1. ユーザーが `wt clean -i` を実行。
2. 画面に worktree の一覧（`wt list` と同等のリッチな情報：最終コミット日時、クリーン/ダーティ状態、PR の状態など）が表示される。
3. ユーザーは `Tab` キーを使って、削除したい worktree を複数選択（マーク）する。
4. `Enter` を押すと、選択された worktree のリストと「これらを本当に削除しますか？ (y/N)」という最終確認プロンプトが表示される。
5. `y` で確定すると、選択したすべての worktree を一括で安全に削除（`wt rm` 相当の処理）する。

## Inspiration
- `fzf -m` (multi-select) を活用した、直感的で高速なターミナル上のファイル選択UX。
- `git branch -D` を fzf で包んだ各種の dotfiles スニペットの快適さ。

## Expected Daily Benefit
溜まってしまった不要な worktree 群を、ターミナルから一歩も出ることなく、目視確認しながら数秒で一掃できるようになる。ディスクスペースの解放や `wt list` の視認性向上が手軽に行えるため、常にクリーンな作業環境を維持するモチベーションが保たれる。

## Scope and Non-Goals
- **ダーティな worktree の強制削除**: 変更が残っている（dirty）worktree を選択した場合でも、デフォルトでは安全のためにエラーまたは警告を出してスキップする。強制削除（`--force`）の統合は、慎重なオプション設計が必要なため第一段階ではスコープ外とする。
- **TUI ツールとの競合**: 既に `easy-worktree-tui` が存在するが、TUI をインストールしていないユーザー向けに CLI 単体で完結する軽量なリストクリーナーを提供する位置付けとする。

## Risks or Open Questions
- **`fzf` への依存強化**: 既に `wt select` で `fzf` は活用されているが、複数選択の UI を美しく見せるためのフォーマット文字列（カラム幅の調整など）が複雑になりやすい。
- **誤操作による削除**: 複数選択して Enter を押した直後に消えてしまうと危険なため、必ず削除前の最終確認（Dry-run 的なリスト表示と y/N プロンプト）を挟む設計が必須。

## Suggested Rollout
1. 内部的に `wt list` の出力を `fzf -m` にパイプし、選択結果を受け取るロジックを実装する。
2. 削除前に確認プロンプト（「以下の N 件の worktree を削除します。よろしいですか？」）を表示するフェーズを追加する。
3. `wt clean -i` オプションとして公開し、ユーザーフィードバックを得る。
