# `wt select` の対話的選択における MRU (最近使った順) ソートの導入

## Summary
`wt select` (引数なし) による `fzf` 選択画面の並び順を、現在の作成日時順などではなく「最近アクセス（select）した順 (Most Recently Used)」に変更する改善。

## Problem
現在、`wt select` でインタラクティブにワークツリーを切り替える際、一覧はおそらく作成日時順 (Created) などで表示されている。
現実の開発では、長期間の大きめな機能開発（作成日が古い）と、日々の細かいバグ修正（作成日が新しい）を並行して進めることがよくある。この場合、頻繁に行き来するはずの古いワークツリーが一覧の下の方に埋もれてしまい、毎回 `fzf` で名前の一部をタイピングして検索する手間（摩擦）が生じている。
直前にいたワークツリーには `wt select -` で戻れるが、「3つ前にいたワークツリー」や「昨日から裏で並行作業しているもう1つのタスク」を探すときにはカバーしきれない。

## Proposal
`wt select` を実行してワークツリーに切り替えるたびに「最終アクセス日時（Last Accessed）」をメタデータとして記録・更新する。
そして、`wt select` を引数なしで実行した際の `fzf` の並び順を、この MRU (Most Recently Used) 順に変更する。

**挙動:**
1. ユーザーが `wt select feature-A` を実行して切り替える（アクセス日時が更新される）。
2. 別のワークツリーに移動した後、再び `wt select` (引数なし) を実行する。
3. `fzf` のリストの最上位（または最下位など選択しやすい位置）に、直前までいた `feature-A` などの「最近使ったワークツリー」が順番に並ぶ。

## Inspiration
- エディタ（VSCode など）の `Ctrl+Tab` や `Cmd+P`（Quick Open）における「最近開いたファイル」の並び順の快適さ。
- `z` や `zoxide` といったディレクトリジャンプツールにおける、Freency（頻度と最近の利用）ベースの最適化。

## Expected Daily Benefit
ターミナル上で複数のタスクを切り替える際、`wt sl` と打つだけで「いま自分がアクティブに進めているタスク」群が常にトップに表示されるようになる。名前を思い出してタイピングする無駄がなくなり、数回のキーストローク（矢印キーと Enter）だけで瞬時にコンテキストスイッチが可能になる。

## Scope and Non-Goals
- **Scope**: `wt select` での移動イベントをトリガーとしたアクセス日時の記録と、`wt select` (対話モード) のデフォルトソート順の変更。`wt list` コマンドに `--sort accessed` のようなオプションを追加すること。
- **Non-Goals**: シェル標準の `cd` コマンド等による手動移動までをフックして追跡することは、複雑性を増すためスコープ外とする。

## Risks or Open Questions
- **メタデータの保存とパフォーマンス**: 現在、作成日時などのメタデータは `$XDG_CONFIG_HOME/easy-worktree/` 下で管理されている。`select` のたびにここへ書き込みが発生するが、パフォーマンスや競合に問題が出ないか考慮が必要。
- **`Last Commit` との比較**: `wt list --sort last-commit` を `fzf` のデフォルトにするという代替案もある。コミットを伴う作業であればこれでも十分だが、「単にコードを読みに移動しただけ」のワークツリーは Last Commit 順だと上がってこないため、体感的な「さっきまで作業していた場所」とはズレる可能性がある。やはり MRU 記録が望ましい。

## Suggested Rollout
1. `wt select` 時のフックでメタデータ（`accessed_at`）を記録する処理を追加する。
2. `wt list --sort accessed` を実装する。
3. 対話モード (`wt select` 無引数) で `fzf` に渡すリストのデフォルトソートを `--sort accessed` に変更する。
