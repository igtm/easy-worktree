# `wt tmp` (Ephemeral Worktrees) コマンドの追加

## Summary
一時的な作業やコード確認のためだけに使い、作業終了後（サブシェルを抜けた際など）に自動でクリーンアップされる「使い捨て（Ephemeral）」のワークツリーを作成する `wt tmp` コマンドを提案します。

## Problem
別のブランチのコード構造を少し確認したい、テストだけ回したい、過去の特定のコミットの挙動を調べたい、といったケースが日常開発で多発します。
現状の `wt add` では、これらの一時的な目的でも通常のワークツリーとして作成され、後から `wt rm` や `wt clean` で手動で削除する手間が発生します。結果として `wt list` に「ちょっと見ただけ」のワークツリーがゴミとして溜まりやすくなり、作成と削除のライフサイクル管理が負担になります。

## Proposal
`wt tmp` コマンドを新設します。

1. **自動命名と作成**: `wt tmp [<commit-ish>]` を実行すると、ランダムな名前（例: `tmp-a1b2c3`）またはプレフィックス付きでワークツリーを作成し、即座に `select` してサブシェルに入ります。
2. **自動クリーンアップ**: ユーザーがそのサブシェルを `exit`（または `Ctrl-D`）で抜けたタイミングで、自動的にそのワークツリーと一時ブランチの削除（`wt rm`）を試みます。
3. **安全装置**: もし未コミットの変更がある場合は「変更がありますが本当に削除しますか？ [y/N]」のプロンプトを出し、意図しないデータ消失を防ぎます。

## Inspiration
- `mktemp -d` コマンドの「使い捨てディレクトリ」の概念
- `git worktree add --detach` の一時的な利用パターン
- 各種コンテナツール（Docker 等）における `--rm`（終了時自動削除）オプション

## Expected Daily Benefit
- 「ちょっと別のブランチを見に行く」「別環境でビルドだけ試す」という行動の心理的・手続的ハードルが下がり、メインの作業コンテキストを汚さずに済みます。
- ワークツリーの一覧が一時的なディレクトリで散らからなくなり、本当に長期間管理すべき機能ブランチのワークツリーだけが綺麗に保たれます。

## Scope and Non-Goals
- **Scope**: 一時ワークツリーの作成機能、サブシェル終了をフックした自動削除プロンプトの表示、未追跡ファイルや変更の安全な破棄確認。
- **Non-Goals**: 複雑なセッション復元機能や、一時ワークツリーから永続ワークツリーへの高度な昇格機能（まずは単に消すことをゴールとする）。

## Risks or Open Questions
- **異常終了時のゴミ残り**: サブシェルを強制終了（Kill）した場合や、ターミナルエミュレータごと閉じた場合、自動削除処理が走らずにゴミが残る問題があります。これは既存の `wt clean` コマンドの拡張（例: `wt clean --tmp` で古い tmp を一掃する機能）でカバーできると考えられます。
- **一時ブランチの扱い**: ブランチを作成せずに Detached HEAD でチェックアウトするオプション（`git worktree add --detach` 相当）をデフォルトにするか、一時的なローカルブランチを作るか。一時ブランチを作った方が実験的なコミットをしやすいため、使い勝手が良さそうです。

## Suggested Rollout
1. `wt tmp` コマンドを実装し、ランダム名でのワークツリー作成とサブシェル起動を行う MVP を提供する。
2. サブシェルのプロンプト表示環境変数（`WT_SESSION_NAME`）などを利用し、使い捨て環境であることを視覚的に強調する（プロンプトを黄色や赤にするなど）。
3. サブシェル終了後の後処理として、対話的な削除プロンプトを実装する。
