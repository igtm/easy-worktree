# ワークツリーに短い説明やメモを付与する機能 (`wt note`)

## Summary
ワークツリーごとに短い説明文（メモ）を保存し、`wt list` の一覧で確認できるようにする機能の提案です。

## Problem
複数のワークツリーを並行して作成し、数日〜数週間放置していると、「このワークツリーでどこまで作業したか」「具体的に何のバグを追っていたのか」が分からなくなることがよくあります。
ブランチ名だけでは作業の文脈や現在のステータスを完全に伝えきれず、思い出すためにわざわざ `wt select` で移動して `git diff` や `git log` を確認しなければならず、切り替えの摩擦となっていました。

## Proposal
ワークツリーに対して1行程度のメモを付与・確認できる機能を追加します。

1. **メモの付与・編集:**
   - 既存のワークツリーに対して `wt note <name> "APIのレスポンス改善の検証中"` のようにメモを追加・上書きできるようにします。
   - 引数なしで `wt note` または `wt note <name>` を実行した場合は、エディタが開くか対話的プロンプトで編集できるようにします。
2. **作成時のメモ付与:**
   - `wt add feature-x -m "○○のバグ再現用"` のように、ワークツリー作成と同時にメモを付与するオプション（`-m` / `--message` / `--note`）を追加します。
3. **一覧表示:**
   - `wt list` コマンドの出力に `Note`（または `Description`）カラムを追加し、付与されたメモを一覧表示します。

## Inspiration
- `git branch --edit-description` : Git 標準の機能ですが、確認するためには特別なコマンドが必要で、一覧性や視認性が低いという課題があります。
- `jj` (Jujutsu) 等の次世代 VCS における、各リビジョンに対する自動説明や付加情報の扱い。

## Expected Daily Benefit
`wt list` を見ただけで、それぞれのワークツリーが「何の目的で作られたか」「今どういう状態か（例: "PRレビュー待ち", "WIP: テストが落ちる" など）」が一目で把握できるようになります。
これにより、「とりあえず作業領域を作って、後でまた戻ってくる」といった非同期な割り込み作業の再開が圧倒的にスムーズになります。

## Scope and Non-Goals
- 長文のドキュメント（README等）をワークツリー内に自動生成・管理することはスコープ外です。あくまで `wt list` で表示可能な1行程度の「メモ」を対象とします。
- メモのバージョン管理（Git履歴に残すなど）は必須としません。あくまで `easy-worktree` のローカルなメタデータとして管理します。

## Risks or Open Questions
- **表示幅の問題**: `wt list` に新しいカラムを追加すると、ターミナルの幅に収まりきらなくなる可能性があります。ターミナル幅に合わせてメモを省略（`...`）する処理や、表示カラムを切り替えるオプション（例: `wt list --verbose`）が必要になるかもしれません。
- **保存場所**: メモデータを各ワークツリー内の `.wt/note` のようなファイルに保存するか、それとも `$XDG_CONFIG_HOME/easy-worktree/` のようなグローバルなメタデータファイルに集約するか。`wt list` での読み込みパフォーマンス（ディスクI/O）を考慮すると、集約して管理する設計が良いかもしれません。

## Suggested Rollout
1. メタデータ保存の仕組み（既存の作成日時メタデータ管理の拡張など）の設計
2. `wt note` コマンドの実装と保存処理
3. `wt list` のフォーマット修正（ターミナル幅の取得と文字の切り詰め処理を含む）
4. `wt add` コマンドへのオプション追加
