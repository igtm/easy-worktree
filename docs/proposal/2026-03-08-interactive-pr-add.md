# `wt pr add` の対話的（インタラクティブ）選択のサポート

## Summary
`wt pr add` コマンドを引数なしで実行した際、リポジトリ内のオープンな PR 一覧を `fzf` で表示し、対話的に選択して worktree を作成できるようにする。

## Problem
現在、他メンバーの PR をローカルでレビューしたり動作確認したりする場合、`wt pr add <number>` を使うことで簡単に worktree を作成できる。しかし、このコマンドを実行するためには事前に「PR 番号」を知っている必要がある。
通常、ユーザーは以下の手順を踏まざるを得ない。
1. ブラウザで GitHub を開く、またはターミナルで `gh pr list` を実行して PR の一覧を見る。
2. 目的の PR の番号を探してコピー・記憶する。
3. `wt pr add 123` のように番号を手打ちして実行する。

この「PR 番号を調べる」というコンテキストスイッチや、ターミナルとブラウザの往復が、日々のレビュー業務において小さな摩擦（面倒くささ）となっている。

## Proposal
`wt pr add` コマンドに引数が与えられなかった場合の挙動を拡張し、`fzf` を用いたインタラクティブな選択 UI を提供する。

**挙動:**
1. `wt pr add` が引数なしで呼ばれた場合、内部で `gh pr list --state open --limit 50 --json number,title,author` などを実行して PR の情報を取得する。
2. 取得したリストをフォーマットし（例: `#123: Add feature X (by @alice)`）、`fzf` にパイプしてユーザーに選択させる。
3. ユーザーが `fzf` 上で Enter を押して選択したら、その行から PR 番号を抽出して `wt pr add <選択した番号>` として処理を続行する。

## Inspiration
- `wt select` を引数なしで実行した場合の `fzf` によるワークツリー選択の快適さ。
- `gh pr checkout` が提供している対話的なブランチチェックアウト体験。

## Expected Daily Benefit
PR のレビューや他メンバーの作業ブランチへの参加が、ターミナル上で `wt pr add` と打って選ぶだけで完結するようになる。ブラウザを開いたり番号をコピペしたりする手間が省け、コードレビューに取り掛かる心理的ハードルが劇的に下がる。

## Scope and Non-Goals
- **PR 検索機能の高度化**: `fzf` の標準的な曖昧検索機能に任せ、`wt` 側で複雑なフィルタリングクエリ（例: 特定のラベルのみ表示など）をパースすることはスコープ外とする。
- **クローズされた PR の復元**: 対象はオープンな PR に限定する。

## Risks or Open Questions
- **`gh` コマンドへの依存と速度**: 現在も PR 関連は `gh` に依存しているが、リスト取得により API 呼び出しが発生するため、ネットワーク環境によっては起動に数秒のラグが生じる可能性がある。UX を損なわないため、取得中は「Loading PRs...」のようなスピナーを出すか、シンプルに標準エラー出力で待機中であることを明示する必要がある。
- **表示のフォーマット**: ターミナルの幅に対して長すぎる PR タイトルが見切れる場合のフォーマット調整。

## Suggested Rollout
1. `gh pr list` を用いた対話的な単一 PR 選択機能を実装する。
2. ネットワーク待ち時間の UX 向上（ローディング表示など）を行う。
3. 必要に応じて、`fzf` のプレビューウィンドウ（PR の詳細説明を表示するなど）への拡張を検討する。
