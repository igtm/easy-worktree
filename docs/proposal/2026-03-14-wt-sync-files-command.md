# `wt sync-files` コマンドによる複数ワークツリー間の設定ファイル一斉同期

## Summary
現在のワークツリーで更新した設定ファイル（`.env` など）を、他の複数のワークツリーへ一斉にコピー（同期）する `wt sync-files` または `wt broadcast` コマンドの提案。

## Problem
`easy-worktree` には `setup_files` によりワークツリー作成時に `.env` 等を自動コピーする機能がある。しかし、開発を進める中で「新しい環境変数を追加した」「共通の設定ファイルを修正した」という場合、既に作成済みの他のワークツリーにはその変更が反映されない。
`setup_links`（Symlink）機能で一元管理する解決策もあるが、ワークツリーごとに微妙に値を変えたい（例: ローカルサーバーのポート番号を分ける、異なる DB を向かせる等）ケースでは Symlink は使えず、実体のコピーが必要になる。
結果として、他のワークツリーに切り替えた際に設定漏れでサーバーが起動せず、原因究明に時間を取られたり、手動で各ディレクトリにコピーして回るという地味だが確実な摩擦（認知負荷）が発生している。

## Proposal
現在のワークツリーに存在するファイルを、他のワークツリーに一斉配信・同期するコマンドを追加する。

**使用イメージ:**
```bash
# wt の設定ファイル(setup_files)に定義されたファイルを全ワークツリーに同期
wt sync-files

# 特定のファイルを指定して同期
wt sync-files .env.local

# fzf等で同期先のワークツリーをインタラクティブに選択して実行
wt sync-files -i
```

## Inspiration
- Tmux の `synchronize-panes` (キー入力を複数ペインにブロードキャストする機能)。
- 構成管理ツールのマルチターゲット配布機能。

## Expected Daily Benefit
新しい環境変数の追加や、Linter・エディタ設定の更新などを1つのワークツリーで行った直後に `wt sync-files` を実行するだけで、手元の全作業環境が最新の状態に保たれる。
「別ブランチに切り替えたらなぜか動かない」という環境起因のトラブルを未然に防ぎ、安心して複数タスクの並行作業を行えるようになる。

## Scope and Non-Goals
- **Scope**: 現在のファイル群を他ワークツリーの同名パスへ上書きコピーする処理。上書き前にバックアップ（`.env.bak`など）を作成する安全機構。
- **Non-Goals**: 高度な 3-way マージや行単位での差分マージ機能の実装。あくまでファイル全体の上書き（または追記）を基本とし、複雑なマージは Git や専用の Diff ツールに委ねる。

## Risks or Open Questions
- **意図しない上書きによるデータ消失**: 各ワークツリーで独自に設定していたパスワードやポート番号が上書きされて消えるリスクがある。
  - **対策**: 同期実行時に「上書きされるファイルと対象ワークツリーのリスト」を事前表示して確認 (y/N) を求める。また、コピー前に元のファイルを自動で `.bak` として退避する。
- **対象を絞る仕組み**: マージ済みの古いワークツリーにまで同期するのは無駄なため、デフォルトでは「現在 active / clean でない」最近使われたワークツリーに限定するか、インタラクティブ選択を基本とするか。

## Suggested Rollout
1. `wt sync-files <file>` のように単一ファイルを引数に取り、確認プロンプトを出した上で全ワークツリーへ上書きコピーするシンプルな MVP を実装。
2. 上書き前の `.bak` バックアップ作成機能を導入し安全性を担保する。
3. `setup_files` 設定と連携し、引数なしで一括同期できる機能を追加。
