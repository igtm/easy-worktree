# 提案: サブシェル起動を伴わないディレクトリ切り替え (Shell Function Integration)

## Summary
現在の `wt select` は新しいサブシェルを起動して worktree に「ジャンプ」する仕組みですが、ネストされたシェルの警告やシェル履歴（history）の分断といった課題があります。
これを解決するため、`zoxide` のようなアプローチで、現在のシェル環境に直接介入して `cd` を実行できる「Shell Function Integration」を提案します。

## Problem
`easy-worktree` の大きな魅力は特別な設定なしに `wt select` で即座に worktree にジャンプできる点ですが、その実装はサブシェル（新しいプロセス）の起動に依存しています。
このアプローチには以下の摩擦が伴います：
1. **シェルのネスト問題**: すでに `wt` のサブシェル内にいる状態で別の worktree に切り替えると警告が出ます。何度も切り替えるとプロセスが深くネストされ、何度も `exit` する手間が発生します。
2. **History の分断**: サブシェル内で行ったコマンド履歴が、親シェルや他のペインと綺麗に同期されにくくなります。
3. **環境変数の汚染**: サブシェル内で export した環境変数が、終了後に消えるのは利点でもありますが、意図せず引き継がれる場合などに混乱を招きます。

## Proposal
シェルの初期化スクリプト (`~/.zshrc` や `~/.bashrc`) に1行追加することで、`wt` コマンドをシェル関数としてラップし、サブシェルを起動せずに直接 `cd` できるオプトイン機能を追加します。

1. **初期化コマンドの追加**
   ```bash
   eval "$(wt init zsh)"  # または bash, fish
   ```
   これを実行すると、シェル内に `wt` という名前のラッパー関数が定義されます。

2. **ラッパー関数の挙動**
   シェル関数は `wt` が呼ばれた際、実体の CLI をフックします。
   もし `wt select <name>` が呼ばれた場合、CLI から出力されたターゲットディレクトリのパスを受け取り、**現在のシェルで `cd /path/to/worktree` を実行**します。
   それ以外のコマンド (`wt list`, `wt add` など) はそのままバイパスして CLI 実行ファイルに渡します。

3. **後方互換性と段階的導入**
   特別な設定をしたくないユーザーのために、従来のサブシェル起動方式はそのままデフォルト動作として残します。
   `eval "$(wt init zsh)"` を設定したユーザーのみ、ネスト警告のないシームレスな体験（History 共有、サブシェル不要）を得られるようにします。

## Inspiration
- **zoxide**, **cdpath**, **nvm**: シェル関数を利用して現在のプロセス内でディレクトリ移動や環境変数変更を行う標準的なアプローチ。
- 現在の `easy-worktree` の設計思想「特別な設定なしで使える」を尊重しつつ、ヘビーユーザー向けの「設定すればさらに便利になる」パスを提供します。

## Expected Daily Benefit
- worktree 間を何度往復してもサブシェルがネストしないため、警告メッセージがなくなり、メモリ使用量も増えません。
- `exit` を連打して元のディレクトリに戻る必要がなくなり、履歴（history）の連続性が保たれるため、コマンド検索（Ctrl+R）などの DX が劇的に向上します。

## Scope and Non-Goals
- **スコープ**: `zsh`, `bash`, `fish` 向けのラッパー関数の出力と、CLI 側のフック用出力オプション（例: `wt _locate <name>`）の実装。
- **非目標**: 従来のサブシェル方式の完全廃止（ゼロコンフィグという利点を維持するため、デフォルトとしては残します）。

## Risks or Open Questions
- すでに `.tmux.conf` 等で `wt current` を表示しているユーザーの環境において、サブシェルが起動しない場合に環境変数 `$WT_SESSION_NAME` をどうやって更新するか。
  - 解決案: ラッパー関数内で `cd` するのと同時に `export WT_SESSION_NAME=<name>` も行うことで、全く同じようにプロンプト等を機能させることができます。

## Suggested Rollout
1. `wt _locate <name>` のような、対象のパスと環境変数を返す内部コマンド（または `--print-path` オプション）を CLI に実装。
2. `wt init <shell>` コマンドを実装し、シェルスクリプト文字列を出力。
3. README に上級者向け・ヘビーユーザー向けのセットアップ手順として記載。
