# `wt pin` コマンドによるワークツリーの保護と固定表示

## Summary

特定のワークツリーを「ピン留め（保護）」し、`wt clean` による意図しない一括削除から守るとともに、`wt list` や `wt select` の一覧で常に上位に表示させる機能の提案です。

## Problem

現状の `easy-worktree` には以下のような課題があります。
1. **意図しない削除のリスク**: `wt clean --all` や `wt clean --days 30` は非常に便利ですが、長期間保持しておきたい検証用ワークツリー（例: `playground`, `review-env`）や、数週間かけて進めている巨大なリファクタリングブランチが巻き込まれる危険性があります。ローカルに変更があれば削除されませんが、コミット済みのきれいな状態だと削除されてしまいます。
2. **一覧性の低下**: 頻繁にアクセスする特定のワークツリーが、新しく作成された他のタスク用ワークツリーに埋もれてしまい、`wt list` や `wt select` 時の視認性が下がることがあります（`--sort last-commit` 等を使っても、一時的な作業で順位が変動します）。

## Proposal

以下の機能を追加します。

1. **`wt pin <name>` / `wt unpin <name>` コマンド**
   - 指定したワークツリーをピン留め（または解除）します。
   - 実装としては、該当ワークツリーのメタデータ（例: `$XDG_CONFIG_HOME/easy-worktree/` 配下、またはローカルの `.wt/config.local.toml`）に `pinned = true` を記録します。

2. **`wt clean` からの保護**
   - ピン留めされたワークツリーは、ローカルの変更有無にかかわらず、すべての `wt clean` コマンド（`--all`, `--merged`, `--closed`, `--days`）の自動削除対象から完全に除外されます。
   - `wt rm <name>` で明示的に指定された場合のみ、確認プロンプト（「保護されていますが本当に削除しますか？」）を出した上で削除可能とします。

3. **リスト表示での優先と可視化**
   - `wt list` の出力で、ワークツリー名の横にピンマーク (📌) を表示します。
   - `wt list` および `wt select` (fzf) において、ソート順を無視して常に最上位（または専用のセクション）にグループ化して表示します。

## Inspiration

- **Slack / Discord のピン留めチャンネル**: 多数の動的なチャンネルの中で、常に使うものを上部に固定する体験。
- **ブラウザのタブ固定**: 誤って閉じてしまうのを防ぎ、かつ左端に小さく固定する機能。
- **GitKraken 等の GUI クライアント**: 特定のブランチや WIP 状態を「お気に入り」として固定する機能。

## Expected Daily Benefit

- `wt clean --all --yes` のような強気なクリーンアップコマンドを、心理的安全性を保ったまま日常的に実行できるようになります。
- 日々の開発で「ベースとなるレビュー環境」や「サンドボックス環境」への切り替えが、`wt select` から一切探すことなく最速で行えるようになります。

## Scope and Non-Goals

- **Scope**:
  - `wt pin` / `wt unpin` コマンドの実装。
  - `wt clean` コマンドの削除対象判定ロジックの修正。
  - `wt list` および `wt select` における表示とソート順の修正。
- **Non-Goals**:
  - ピン留めされたワークツリー同士の詳細な手動並び替え（ピン留め内は作成日や最終コミット日でのソートで十分）。
  - リモートリポジトリとのピン留め状態の同期（あくまで個人のローカル環境における利便性と安全性のための機能です）。

## Risks or Open Questions

- **メタデータの保存場所**: ピン留め状態をどこに保存するか。ワークツリーごとの `.wt/` 内のローカル設定に保存するか、グローバルなメタデータディレクトリに保存するか。
  - *案*: ワークツリーディレクトリそのものが削除される事故を防ぐためという性質上、メタデータ側で一元管理する方が実装がシンプルになる可能性があります。

## Suggested Rollout

1. ピン留めのメタデータ記録と `wt pin` / `wt unpin` の実装
2. `wt clean` における保護ロジックの追加（安全性の確保を優先）
3. `wt list` および `wt select` での UI 反映（📌 アイコンの追加と上位ソート）
