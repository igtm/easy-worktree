# `wt foreach` コマンドによる全ワークツリーへの一括コマンド実行

## Summary
現在アクティブなすべてのワークツリー（または条件で絞り込んだワークツリー）に対して、指定した任意のコマンドを一括で実行する `wt foreach <command>` コマンドを提案します。

## Problem
複数のワークツリーを並行して作業している際、以下のような「すべてのワークツリーで同じ操作をしたい」というケースが頻繁に発生します。
- リポジトリ全体で共通の依存関係が更新されたため、全ワークツリーで `npm install` や `pip install` を再実行したい。
- 全てのワークツリーで `git fetch` や `git pull` を実行して最新の情報を取得したい。
- プロジェクトのビルドスクリプトやフォーマッター (`make format` など) を全ワークツリーで実行したい。

現状では、各ワークツリーに `wt select` で順番に切り替えてコマンドを実行するか、手動でシェルスクリプトを書いて `.worktrees/*` に対してループ処理を回す必要があり、非常に手間がかかります。

## Proposal
`wt foreach` コマンドを追加し、管理下の各ワークツリーのディレクトリで指定したコマンドを順番に実行できるようにします。

**使用例:**
```bash
# 全ワークツリーで npm install を実行
wt foreach npm install

# 全ワークツリーの git status を簡潔に表示
wt foreach git status -s

# 実行するコマンドにフラグが含まれる場合は -- で区切る
wt foreach -- make clean
```

**機能要件:**
- コマンドの出力には、どのワークツリーでの実行結果かが一目で分かるようにプレフィックス（例: `[feature-A] ...`）を付ける、または実行開始前にワークツリー名をヘッダとして出力する。
- コマンドが失敗（終了コード != 0）したワークツリーがあった場合、そこで処理を中断するか、最後まで実行して最後にサマリを出すかをオプションで制御できる（デフォルトは `git submodule foreach` に倣って失敗で中断を推奨）。
- `main` / `base` ワークツリーを含めるかどうかを制御できる（デフォルトは含める）。

## Inspiration
- `git submodule foreach`: サブモジュールに対して一括でコマンドを実行する標準機能。
- `pnpm -r` / `yarn workspaces foreach`: モノレポ内の全パッケージで一括実行する機能。これのワークツリー版という位置づけ。
- 既存提案の `wt run` は単一ワークツリーに対する実行ですが、本提案はその複数（一括）版になります。

## Expected Daily Benefit
- 依存関係の更新や一斉のメンテナンス作業など、複数ブランチを横断する定型作業の時間が劇的に短縮されます。
- シェルの `for d in .worktrees/*; do ...` というアドホックなスクリプトを書く必要がなくなり、より直感的で安全な方法で一括処理が可能になります。

## Scope and Non-Goals
- **Scope**: 全ワークツリーのディレクトリの列挙、各ディレクトリでのコマンドの直列実行、出力のハンドリング。
- **Non-Goals**: 高度な並列実行制御や依存関係グラフの解決（単純なループ実行で十分）。複雑なジョブキュー機能の実装。

## Risks or Open Questions
- **対話的コマンドの扱い**: `vim` や対話的なプロンプトを求めるコマンドを一括実行した場合にどう振る舞うべきか。通常は標準入出力をそのまま繋ぐか、警告を出してスキップする等のハンドリングが必要になります。
- **実行の中断**: `Ctrl-C` が押された際、現在のコマンドだけを中断するのか、`foreach` 全体を中断するのかのシグナルハンドリングを適切に行う必要があります。

## Suggested Rollout
1. まずは単純な直列実行のみをサポートした `wt foreach <command>` を実装する。
2. 出力にワークツリー名をわかりやすく表示するロジックを組み込む。
3. 将来的に `--parallel` オプションや、特定の状態のワークツリーのみを対象にするフィルタリングオプションなどを追加していく。
