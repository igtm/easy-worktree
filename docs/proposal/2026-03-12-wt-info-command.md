# `wt info` コマンドによるワークツリー詳細の確認

## Summary
指定したワークツリーに関する詳細情報（パス、ブランチ、PRステータス、未コミット変更、作成日時など）を集約して表示する `wt info` コマンドを追加する提案です。

## Problem
`wt list` は複数ワークツリーの全体把握には優れていますが、個別のワークツリーの詳細なコンテキストを確認するには情報量が制限されています。
たとえば、「このタスクはどこまで進んでいたか」「PRのCIは通っているか、誰のレビュー待ちか」「ローカルに未プッシュのコミットはいくつあるか」を知りたい場合、現状ではわざわざ `wt select` で対象のワークツリーに移動し、`git status` や `gh pr status` を実行する必要があります。
作業を再開するたびにこの定型的な確認作業を行うのは、日々の開発において摩擦となります。

## Proposal
`wt info [<name>]` コマンドを追加し、特定のワークツリーのコンテキストを一目で把握できるようにします。

**表示する情報の例:**
- **Worktree**: 名前と絶対パス
- **Branch**: 現在のブランチ名と、追跡しているリモートブランチ
- **Status**: Clean / Dirty (未コミットファイルの一覧を数件表示)
- **Commits**: ベースブランチからの Ahead / Behind 数
- **PR Info**: 関連するPR番号、タイトル、ステータス(Open/Draft/Merged)、CIステータス、URL (※ `gh` コマンド連携時)
- **Metadata**: 作成日時、ピン留め状態 (`wt pin`)、説明メモ (`wt notes`)

引数 `<name>` を省略した場合は、現在選択している（カレントディレクトリの）ワークツリーの情報を表示します。

## Inspiration
- `gh pr view` や `gh pr status` のターミナルでのサマリー表示。
- `brew info` や `npm info` などのパッケージ詳細表示コマンド。
- `git status` のリッチな代替ツール（`onefetch` や `neofetch` のようなサマリー体験）。

## Expected Daily Benefit
週末を挟んだ後や、他の急ぎのタスクをこなした後に、一時停止していたワークツリーでの作業を再開する際の「思い出しコスト」がほぼゼロになります。
ターミナル上で `wt info feat-x` と打つだけで、次に自分が何をすべきか（コミットすべきか、プッシュすべきか、PRのレビューを待つべきか）が明確になります。

## Scope and Non-Goals
- **スコープ内**: ローカルの Git 情報および連携可能なメタデータ（GitHub PR情報など）の読み取りとフォーマット表示。
- **スコープ外**: このコマンド内から直接設定を変更したり、PRのステータスを操作したりする機能（表示に特化し、操作は `wt config` や `gh pr` などに委ねる）。

## Risks or Open Questions
- **レスポンス速度**: GitHub PR の情報を取得するためにネットワークアクセス（`gh` コマンドの呼び出し）が発生すると、表示がワンテンポ遅れる可能性があります。ローカル情報（Gitステータスなど）を先に表示し、PR情報は非同期で取得してスピナー表示にするなど、体感速度を落とさない工夫が必要かもしれません。
- **出力の冗長性**: 未コミットのファイルが大量にある場合に画面が埋め尽くされないよう、表示件数に上限（例: 5件まで表示して残りは `...and 3 more` とする）を設けるべきです。

## Suggested Rollout
1. まずはネットワークアクセスを伴わないローカルの Git 情報（パス、ブランチ、Dirty/Clean、Ahead/Behind）をきれいにフォーマットして出力する MVP を実装する。
2. 次に、`gh` CLI が利用可能な場合に PR 情報（URL、ステータス）を同期的に取得・追加表示する。
3. （必要に応じて）非同期取得による UX 改善と、メタデータ（ピン留め、メモなど）への対応を行う。
