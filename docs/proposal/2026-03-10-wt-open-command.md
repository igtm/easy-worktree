# `wt open` コマンドおよび `--open` オプションによるエディタ連携

## Summary

ワークツリーを即座にデフォルトエディタ（VS Code, Cursor, Neovim等）で開くための `wt open` コマンド、および `wt add <name> --open` オプションを追加する提案です。

## Problem

現在、新しいタスクに取り掛かる際、ターミナルで `wt add feature-A --select` を実行し、その後にサブシェル内で `code .` や `cursor .` を実行してエディタを立ち上げる、という手順が一般的です。
しかし、ターミナル上ではディレクトリを移動（`wt select`）したいわけではなく、「単にそのワークツリーのコードをエディタで開きたい」だけのケースが多々あります。
特に、バックグラウンドで複数のワークツリーをエディタで開いて見比べるような場合、いちいち `wt select` でシェルをネストさせたり、パスを調べて `code .worktrees/feature-A` と打つのは非常に手間です。

## Proposal

以下の機能を追加します。

1. **`wt open [<name>]` コマンド**
   - 指定したワークツリーのディレクトリを `$EDITOR` または環境変数 `$WT_EDITOR`（未設定の場合は `code` 等の一般的なエディタをフォールバックとして試行）で開きます。
   - `<name>` を省略した場合は、`wt select` と同様に `fzf` 等によるインタラクティブな選択UIを提供します。

2. **`wt add <name> --open` (ショートカット: `-o`)**
   - ワークツリーを作成した直後に、そのディレクトリをエディタで開きます。
   - `--select` の代わり、あるいは併用として使用できます。

## Inspiration

- **gh repo view --web / gh pr view --web**: ブラウザで即座に開く機能がDXを劇的に向上させているのと同様に、ローカル環境でも「即座に開く」コマンドは有用です。
- **tmuxinator / tmux-sessionizer**: プロジェクトを選択すると同時にエディタと環境が立ち上がる体験。
- **GitKraken / GitHub Desktop**: UIから「エディタで開く」ボタンをワンクリックする体験をCLIに持ち込みます。

## Expected Daily Benefit

- 「ブランチ作成 → エディタ起動」の反復プロセスから無駄なキーストロークとサブシェルのネストが消滅します。
- 複数のワークツリーを並行してレビュー・編集する際、わざわざターミナルで対象ワークツリーに `cd` せずとも、`wt open` から素早くエディタウィンドウを増やすことができます。
- GUIエディタを中心としたワークフローを持つ開発者にとって、`wt` の利用障壁が大幅に下がります。

## Scope and Non-Goals

- **Scope**:
  - `$EDITOR` や `$VISUAL`、専用の `$WT_EDITOR` 環境変数の解釈。
  - `wt open` コマンドの実装とインタラクティブ選択（`fzf`）。
  - `wt add` への `--open` オプションの追加。
- **Non-Goals**:
  - 特定のエディタ（VS Codeなど）に強く依存した拡張機能の提供。あくまでOSのコマンド呼び出しとして実装します。
  - ターミナルマルチプレクサ（tmux等）のペイン分割など、エディタ以外のターミナルレイアウト管理。（それは別の提案で扱うべき範囲です）

## Risks or Open Questions

- **エディタのブロック動作**: コマンドラインからエディタを起動した際、フォアグラウンドでブロックされるエディタ（例: `vim`）と、即座に制御を返すエディタ（例: `code`）があります。`wt open` 実行時にブロックされるのが期待する動作か、バックグラウンド実行を強制すべきか？
  - *案*: `$EDITOR` がCUI系（vim, nvim, nano等）かGUI系かに応じて挙動を変えるのは難しいため、標準ではそのまま `subprocess.run` 等で実行（CUIエディタならそのままシェルを乗っ取る）し、GUIエディタなら勝手にデタッチされるのに任せるのがシンプルです。
- **デフォルトエディタの解決**: 環境変数が何も設定されていない環境（特にWindowsやクリーンなmacOS）でのフォールバック挙動をどうするか。

## Suggested Rollout

1. 環境変数の解決ロジックおよび `wt open <name>` の基本実装を追加。
2. 引数なし時のインタラクティブ選択（`fzf`）を追加。
3. `wt add` に `--open` オプションを追加。
