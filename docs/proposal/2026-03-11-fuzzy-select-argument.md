# `wt select` の引数における部分一致（Fuzzy / Prefix matching）のサポート

## Summary

`wt select <query>` コマンド実行時、指定された文字列が完全一致するワークツリー名を持たない場合でも、部分一致（あるいは前方一致）で検索し、候補が1件に絞れれば即座に切り替える機能の提案です。

## Problem

現在の `easy-worktree` において、ワークツリーを切り替える方法は以下の2つが主です。
1. `wt select <name>` で正確な名前を指定して即座に切り替える。
2. `wt select` (引数なし) で `fzf` のインタラクティブな UI を開き、検索して切り替える。

ブランチ名が長い場合（例: `feature/JIRA-1234-login-page-redesign`）、CLI で毎回正確な名前を打ち込むのは手間がかかります。一方で、インタラクティブ UI は視覚的に分かりやすいものの、「このブランチに行きたい」と明確な意図がある（かつユニークな部分文字列を知っている）場合には、画面が切り替わるワンクッションの動作が思考の妨げになる（フロー状態を削ぐ）ことがあります。

## Proposal

`wt select <query>` （またはエイリアスの `wt sl <query>`）に対して、以下の挙動を追加します。

1. **完全一致の確認**: まず `<query>` と完全に一致するワークツリーがあれば、従来通りそれに切り替えます。
2. **部分一致（Fuzzy）の検索**: 完全一致がない場合、既存のワークツリー名から `<query>` を部分文字列として含む（あるいは fzf のような fuzzy match を満たす）ものを検索します。
3. **1件のみヒットした場合**: インタラクティブ UI を介さず、即座にそのワークツリーへ切り替えます。
4. **複数ヒットした場合**: ヒットした複数の候補を対象として、自動的に `fzf` のインタラクティブ UI を起動します（可能であれば入力済みの `<query>` を初期クエリとして fzf に渡す）。

## Inspiration

- **zoxide (`z` command)**: `z <部分文字列>` で、ディレクトリ履歴から最もマッチするディレクトリへ即座に移動する体験。複数候補があれば `z -i` や `zi` で選べるアプローチ。
- **git checkout の補完**: 曖昧な入力でもタブ補完で補えるが、それよりもさらに「一発で飛べる」体験。
- **tmux のセッション切り替え**: `tmux attach -t <prefix>` は、プレフィックスがユニークであれば即座にアタッチできる。

## Expected Daily Benefit

- `wt sl log` のように数文字タイプするだけで、目的の `feature/login-page-redesign` に一瞬でジャンプできるようになります。
- インタラクティブUIの起動・描画・選択というコンテキストスイッチを省き、CLI での思考のスピードのままディレクトリ移動が完結します。タイピング数と視線移動の劇的な削減につながります。

## Scope and Non-Goals

- **Scope**:
  - `wt select` コマンドにおける引数の解釈ロジックの改善。
  - 完全一致 → 部分一致（1件） → 部分一致（複数・fzf連携）というフォールバック処理の実装。
- **Non-Goals**:
  - 複雑なスコアリングアルゴリズム（`zoxide` のような frecency 考慮）の導入。まずは単純な部分一致（または正規表現マッチ）による絞り込みで十分とします。

## Risks or Open Questions

- **意図しないワークツリーへのジャンプ**: ユーザーが複数の候補があると思って入力したが、たまたま1件しかヒットせず、意図しないワークツリーにジャンプしてしまう可能性。
  - *対策案*: ジャンプ直後に「どのワークツリーに切り替えたか」を明確に標準出力に出す（現在の `wt select` の挙動でプロンプト等が変わるため、基本的には問題になりにくい）。
- **fzf への初期クエリの渡し方**: `fzf -q <query>` を使うことで、複数ヒット時にユーザーがシームレスに絞り込みを継続できるように実装できるかの確認が必要。

## Suggested Rollout

1. `wt select` の引数評価ロジックに部分一致の検索処理を追加する。
2. 候補数が1件ならそのまま select ロジックへ流す処理を追加する。
3. 複数候補の場合は `fzf -q <query>` として既存のインタラクティブ UI を呼び出す。
